#### 확정한 문서 및 관리 기준

소스 구조와 주요 라이브러리 및 하위 의존성의 관계는
[외부 소스 안내](../../../third_party/README.md)를 기준으로 한다.
설명 목록에는 주요 라이브러리만 나열하고 하위 의존성 및 연결과 빌드 보조 패키지는 묶어서 설명한다.
같은 원본 프로젝트의 구성 요소와 다른 프로젝트의 의존성을 함께 보관한다.
개별 하위 패키지의 출처, 버전과 체크섬은 기존 소스 목록에서 관리한다.

디렉토리별 역할과 Git 관리 범위는 [루트 안내](../../../README.md)에 정리했다.
원본 소스, 연결 및 관리 도구, 검증 코드와 docs 및 specs는 Git으로 관리한다.
생성된 build, 검증 구성의 target, Python 캐시와 로컬 data/todo는 제외한다.
관리 대상을 매 커밋마다 모두 수정해야 한다는 의미는 아니다.

소비자의 선언, 잠금 파일, 기능과 대상 환경에 따른 선택 및 실제 검증 수치는
[Rosemary 연결 안내](../../../docs/rosemary-integration.md)와 verification에 기록한다.

### 발견한 문제와 후속 확인

새 기능 결함과 명세 변경은 없었다.
data/todo를 커밋 대상으로 안내한 오류를 정정하고 제외 규칙을 적용했다.
주요 라이브러리 중심으로 두 README를 정리하고 문서와 Git 관리 범위를 대조했다.

### QA 결과 요약

공급 자료, 문서 보완과 적용 범위의 검토를 마쳤고 사용자 최종 승인을 받았다.
완료 구분은 all_passed이며 미해결 기능 결함과 추가 필수 검사는 없다.

QA 완료 시점의 공급은 작업 트리 변경이며 공급용 커밋 리비전과 Rosemary 인계 파일은 아직 없었다.

QA 완료는 커밋, 푸시 또는 프로젝트 간 인계 실행의 승인이 아니다.

## 사용자 승인

### 완료 구분

all_passed
설계의 QA 항목을 검토하고 문서 보완 및 관리 범위의 대조를 마쳤다.
미해결 기능 결함과 추가 필수 검사가 없으며 최종 결과 및 제외 범위의 사용자 승인을 받았다.

### 사용자 판단

기준 선행 파일은 verification-report-001.md다.
사용자가 검증 결과와 리뷰 의견, 문서 보완과 Linux 검증 범위 및 제외 항목을 확인하고 QA 완료를 승인했다.
주요 라이브러리 중심의 문서 구성과 Git 관리 범위는 위 확정 기준을 따른다.
완료 승인과 함께 specs 문서의 의미를 보존한 본문 정리를 요청했다.

### 보완 요청과 처리 결과

소스 보관과 선택 범위 설명을 소비 안내에 추가했다.
루트 README에 주요 구성과 Git 관리 범위를 정리하고,
third_party/README에 주요 라이브러리의 용도 및 버전과 원본 관리 기준을 정리했다.
전체 하위 패키지의 출처와 체크섬 목록은 유지했다.

.gitignore는 주석 없이 build, /checks/*/target/, Python 캐시와 /data/todo/를 제외한다.
각 제외 규칙의 적용과 관리 대상 소스, 문서, 설정 및 검증 입력 자료의 비제외를 확인했다.
문서 보완 시점의 Git 등록 후보에 생성물과 로컬 할 일이 없고,
등록할 원본 중 제외 규칙에 걸리거나 누락된 파일이 없음을 대조했다.

문서 보완 후 로컬 링크와 주요 라이브러리 버전을 대조했다.
공백 검사와 report 정형 검사는 통과했다.
빌드 및 실행 코드, 의존성 버전과 검증 기준의 변경이 없어 DB 및 소비 테스트는 재실행하지 않았다.
추가 코드 교차 검토도 수행하지 않았다.

specs의 반복 설명과 낡은 대기 표현을 정리하고 확정 요구사항, 검증 결과와 승인 이력을 보존했다.
이전 단계의 미확인 및 인계 문장은 당시 시점을 명시하고 최종 결과에 연결했다.
로컬 요청서와 실행 로그는 Git에서 제외되는 자료로 구분했다.
확정 계약은 논의 기록에 보존하고 준비 단계의 기능 요약은 최종 기능 목록을 참조하도록 정리했다.
검토자 작성 리뷰는 원문을 유지하고 해소된 사항의 최종 판단은 verification에 연결했다.
정리 후 문서의 로컬 링크, 고정 버전과 과거 승인 이력의 보존 및 report 형식을 검사했다.

### 남은 사항과 이관 조건

QA의 미처리 항목은 없다.
QA 완료 시점에는 공급용 커밋과 Rosemary 실제 인계가 남아 있어 원래 두 공급 요청을 진행 상태로 유지했다.
이는 QA 단계의 미완료 또는 재시험 요구를 뜻하지 않는다.
